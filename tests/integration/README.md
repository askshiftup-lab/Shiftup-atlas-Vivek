# Integration Testing Guide

This directory contains integration smoke tests (`test_integration_smoke.py`) designed to validate the **Auth/Account** and **Profile/Interests** services once other engineering teams publish their implementations.

---

## 1. Prerequisites for Running Integration Tests

Integration tests require live services running on accessible HTTP endpoints. They **never** run against in-memory mocks.

### Step 1: Clone and Start the External Services
Clone the respective intern repositories into separate local directories outside this repo:
```bash
# Terminal 1: Auth Service (example port 8001)
git clone <auth-service-repo-url> ../auth-service
cd ../auth-service
# Follow service instructions to start (e.g. uvicorn/flask on port 8001)

# Terminal 2: Profile Service (example port 8002)
git clone <profile-service-repo-url> ../profile-service
cd ../profile-service
# Follow service instructions to start (e.g. uvicorn/flask on port 8002)
```

### Step 2: Configure Environment Variables
Copy `.env.example` to `.env` in this repository root (or export in shell):
```env
ATLAS_AUTH_URL=http://localhost:8001
ATLAS_PROFILE_URL=http://localhost:8002
```

### Step 3: Run the Integration Suite
Execute pytest specifically targeting the `integration` marker:
```bash
pytest -m integration
```

---

## 2. Test Data Strategy & Deterministic Cleanup

1. **Synthetic Data Only**: All integration tests use deterministic test identities generated by the `synthetic_user` fixture (e.g., `user999@example.test`). No real email addresses or third-party accounts are ever touched.
2. **Dedicated Test Namespaces**: Test users use distinct synthetic identifiers to avoid collision with any existing development seeds.
3. **Data Cleanup**:
   - Until services provide explicit test-cleanup hooks (such as `POST /testing/reset` or dedicated teardown endpoints), test runs should target an isolated local database or in-memory sqlite instance configured on the running services.
   - Once approved cleanup endpoints are specified in the official API contracts, teardown routines in `conftest.py` will trigger automatic post-test deletion.

---

## 3. Honesty & Execution Modes

| Environment State | Test Status | Reason |
|---|---|---|
| `ATLAS_AUTH_URL` or `ATLAS_PROFILE_URL` unset | **SKIPPED** | Tests explicitly guard with `pytest.mark.skipif`, preventing false-positive passes. |
| Both URLs configured & reachable | **EXECUTED** | Tests communicate strictly over HTTP using `httpx.Client`. |

> **IMPORTANT**: Passing contract tests under mock mode does **NOT** constitute passed integration tests. Integration tests must always report as `SKIPPED` until live endpoints are wired up.
